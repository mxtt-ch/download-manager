# 多线程异步下载管理器 (Multi-threaded Async Download Manager)
## 项目设计规划说明文档

### 1. 项目概述
本项目是一款基于 **Tauri** 框架和 **Rust** 语言开发的高性能桌面端下载管理工具。利用 Rust 的内存安全与高并发特性，实现极致的异步多线程下载体验。UI 界面采用现代化扁平化设计，兼顾轻量化架构与丰富的功能扩展性。

---

### 2. 技术架构方案
* **前端层 (Frontend):** 采用现代前端框架（如 Vue 3 或 React）结合 TypeScript，通过 Tauri 的 API 与后端通信。负责界面渲染、状态展示及实时图表绘制。
* **后端层 (Backend - Rust):**
    * **Core Engine:** 基于 `tokio` 实现异步运行时，使用 `reqwest` 或更底层的 `hyper` 处理 HTTP/HTTPS 请求。
    * **Multi-threading:** 实现文件的分块（Range 请求）并发下载与合并逻辑。
    * **Database:** 集成 **SQLite**，通过 `sqlx` 或 `rusqlite` 管理任务元数据、历史记录及队列顺序。
    * **Configuration:** 采用 **JSON** 文件存储本地化用户设置（如路径、限速、皮肤等）。
* **安全与系统集成:** 通过 Tauri 注入原生 API，实现剪贴板监听、系统托盘通知、文件关联及浏览器扩展插件通信。

### 4. 核心功能设计逻辑

#### 4.1 异步多线程下载逻辑
1.  **文件探测:** 下载前先发送 `HEAD` 请求，获取文件大小及服务器是否支持 `Accept-Ranges`。
2.  **分块策略:** 若支持断点续传，将文件按大小均匀切分为 N 个块（N 为设定的线程数）。
3.  **并发下载:** Rust 后端启动异步任务，每个线程负责下载特定 Range。
4.  **实时状态反馈:** 后端通过 `tauri::Window::emit` 将各线程的进度实时推送至前端展示（如图 1 的线程信息图表）。
5.  **断点续传:** 实时在 SQLite 中记录已完成的 Range 位点。若程序异常关闭，重启后读取位点继续请求未完成部分。

#### 4.2 数据管理逻辑
* **任务状态机:** 定义任务为 `Pending`, `Downloading`, `Paused`, `Completed`, `Error`, `Merging` 等状态。
* **SQLite 存储:** * `tasks` 表: 存储 URL、文件名、状态、存储路径、队列 ID。
    * `checkpoints` 表: 存储分块下载的 Offset 和进度，用于续传。
    * `queues` 表: 存储队列名称及排序权重。
    * `Categories` 表: 存储分类名称、图标、路径映射关系及自动化操作指令。
    * `SiteAuth` 表: 存储站点的匹配域名、Cookie 信息、Token 凭证（加密存储）、以及已用流量统计。
    * `SpeedPolicy` 表: 存储不同时间段或网络环境下的限速方案。
* **JSON 配置:** 存储 UI 状态（深色模式）、全局下载参数等非关系型偏好数据。

#### 4.3 界面交互设计 (UI/UX)
* **深色模式切换:** 前端利用 CSS 变量实现主题动态切换，Rust 端保存用户的偏好。
* **动态图表:** 全局速率表使用 SVG 路径或 Canvas 实时绘制，反映过去 60 秒的带宽波动。
* **磁盘空间预警:** 实时获取目标驱动器剩余空间，若文件大小超过剩余空间，在新建下载时进行预警。
* **按钮可视化配置:** 在“界面设置”中，用户可勾选显示/隐藏主页面的功能按钮，以保持界面极致简洁。

#### 4.4 自动化引擎 (Automation Engine)

- **规则匹配引擎:** 采用“后缀名 -> 站点域名 -> 协议类型”的三级优先级匹配。
- **触发器系统:** 任务状态变为 `Completed` 时，后台 Rust 线程会根据 `Categories` 表中的 `post_action` 字段触发相应的 OS 系统调用（如解压、打开目录）。

#### 4.5 带宽调度算法

- **流量整形 (Traffic Shaping):** 在 Rust 后端使用 `tokio` 异步节流阀（Rate Limiter）。
- **动态调整逻辑:**
  - 实时监测系统网络流量。
  - 若“网络空闲加速”开启，且系统总流量 < $\text{Threshold}$，则动态增加并发 Chunk 块的获取速率。

### 5. 交互设计细节

- **右键快捷操作:** 在任务列表中右键点击，可快速“更改分类”，系统将自动根据分类的新路径执行文件移动操作。
- **状态栏反馈:** 主页面底部实时显示当前的全局下载/上传速度，并根据“速度限制”的状态显示对应的限速图标。
- **弹窗管理:** 所有设置项（下载、站点、速度）均采用非模态设计，允许用户在调整设置的同时观察后台下载进度的变化。
