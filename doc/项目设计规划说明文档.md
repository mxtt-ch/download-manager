# 多线程异步下载管理器 (Multi-threaded Async Download Manager)
## 项目设计规划说明文档 (V1.0)

### 1. 项目概述
本项目是一款基于 **Tauri** 框架和 **Rust** 语言开发的高性能桌面端下载管理工具。利用 Rust 的内存安全与高并发特性，实现极致的异步多线程下载体验。UI 界面采用现代化扁平化设计，兼顾轻量化架构与丰富的功能扩展性。

---

### 2. 技术架构方案
* **前端层 (Frontend):** 采用现代前端框架（如 Vue 3 或 React）结合 TypeScript，通过 Tauri 的 API 与后端通信。负责界面渲染、状态展示及实时图表绘制。
* **后端层 (Backend - Rust):**
    * **Core Engine:** 基于 `tokio` 实现异步运行时，使用 `reqwest` 或更底层的 `hyper` 处理 HTTP/HTTPS 请求。
    * **Multi-threading:** 实现文件的分块（Range 请求）并发下载与合并逻辑。
    * **Database:** 集成 **SQLite**，通过 `sqlx` 或 `rusqlite` 管理任务元数据、历史记录及队列顺序。
    * **Configuration:** 采用 **JSON** 文件存储本地化用户设置（如路径、限速、皮肤等）。
* **安全与系统集成:** 通过 Tauri 注入原生 API，实现剪贴板监听、系统托盘通知、文件关联及浏览器扩展插件通信。

### 3. 界面布局与模块设计

#### 3.1 主页面 (Main Window)
主页面是用户交互的核心，分为四个逻辑区域：

* **左侧：管理侧边栏 (Sidebar)**
    * **状态统计:** 全部任务、下载中、已暂停、已完成、错误/失败。点击切换右侧列表过滤。
    * **队列管理:** 支持“默认队列”及自定义队列（如：影视、软件、学习）。数据存储于 SQLite。
    * **工具区:** 计划任务、速度限制、站点管理、下载设置（点击跳转至设置弹窗对应栏目）。
    * **底部开关:** 深色/浅色模式切换按钮。
* **上方：操作工具栏 (Toolbar)**
    * **核心操作:** 新建下载、开始、暂停、删除、刷新。
    * **搜索与筛选:** 全局任务名/URL 搜索，高级筛选按钮。
    * **设置入口:** 快速进入配置界面。
* **中间：任务列表区 (Task List)**
    * **表格视图:** 展示文件名、大小、进度条、实时速度、剩余时间、状态、线程数。
    * **交互逻辑:** 支持右键菜单（打开文件夹、复制链接、重新校验等）；支持多选批量操作。
* **下方：任务详情面板 (Detail Panel - 默认收起)**
    * **触发条件:** 单击选中某项下载任务后从底部弹出。
    * **内容选项卡:**
        * *任务详情:* 展示详细的 URL、保存路径、创建/开始时间、MD5/SHA 值等。
        * *线程信息:* **可视化展示**各线程的下载状态、下载区间及实时进度。
        * *文件列表:* 针对 BT/磁力链接，展示内部文件树，支持勾选部分下载。
        * *日志:* 记录该任务的重试、错误及连接历史。
        * *全局统计 (右下角):* 实时折线图展示全局下载/上传速率，磁盘空间水位计（D盘/剩余空间）。

#### 3.2 新建下载弹窗 (New Download Dialog)
* **下载类型切换:** 提供 URL 下载、BT 种子、磁力链接三个选项卡。
* **智能识别:** 自动识别剪贴板内容，若为合法链接则自动填入。
* **基础配置:** 链接输入框、保存路径选择、重命名（可选）、所属队列标签选择。
* **高级选项 (折叠展示):**
    * *线程设置:* 针对单任务手动调整并发线程数（建议 1-32）。
    * *下载设置:* 开启/关闭断点续传、下载完成后自动开始、文件完整性校验。

#### 3.3 设置中心 (Settings Dialog)
设置采用左侧分类导航、右侧表单详情的结构，数据持久化于 `config.json`。

* **下载设置 (核心实现):**
    * *基础设置:* 默认下载路径、同时下载任务数上限（1-10）、单任务最大线程数（1-128）、断点续传开关。
    * *交互反馈:* 下载完成后弹出提示音、自动打开窗口、完成任务后自动关机。
    * *文件冲突处理:* 遇到同名文件时（询问、覆盖、重命名）。
    * *子目录管理:* 按任务名称自动创建子文件夹。
    * *浏览器集成:* 剪贴板自动监控开关；安装 Chrome/Edge/Firefox 扩展插件（显示安装状态）。
    * *文件关联:* 勾选支持的文件类型（.zip, .rar, .iso, .mp4 等）及协议（http, ftp, magnet, ed2k）。

### 4. 核心功能设计逻辑

#### 4.1 异步多线程下载逻辑
1.  **文件探测:** 下载前先发送 `HEAD` 请求，获取文件大小及服务器是否支持 `Accept-Ranges`。
2.  **分块策略:** 若支持断点续传，将文件按大小均匀切分为 N 个块（N 为设定的线程数）。
3.  **并发下载:** Rust 后端启动异步任务，每个线程负责下载特定 Range。
4.  **实时状态反馈:** 后端通过 `tauri::Window::emit` 将各线程的进度实时推送至前端展示（如图 1 的线程信息图表）。
5.  **断点续传:** 实时在 SQLite 中记录已完成的 Range 位点。若程序异常关闭，重启后读取位点继续请求未完成部分。

#### 4.2 数据管理逻辑
* **任务状态机:** 定义任务为 `Pending`, `Downloading`, `Paused`, `Completed`, `Error`, `Merging` 等状态。
* **SQLite 存储:** * `tasks` 表: 存储 URL、文件名、状态、存储路径、队列 ID。
    * `checkpoints` 表: 存储分块下载的 Offset 和进度，用于续传。
    * `queues` 表: 存储队列名称及排序权重。
* **JSON 配置:** 存储 UI 状态（深色模式）、全局下载参数等非关系型偏好数据。

#### 4.3 界面交互设计 (UI/UX)
* **深色模式切换:** 前端利用 CSS 变量实现主题动态切换，Rust 端保存用户的偏好。
* **动态图表:** 全局速率表使用 SVG 路径或 Canvas 实时绘制，反映过去 60 秒的带宽波动。
* **磁盘空间预警:** 实时获取目标驱动器剩余空间，若文件大小超过剩余空间，在新建下载时进行预警。
* **按钮可视化配置:** 在“界面设置”中，用户可勾选显示/隐藏主页面的功能按钮，以保持界面极致简洁。
